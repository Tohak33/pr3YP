# DeviceStore

Интернет-магазин: каталог товаров, корзина, оформление заказа с чеком, личный кабинет и панель администратора.

## Состав проекта

## Как это работает

Браузер обращается к API по адресу `http://localhost:5000/api`, сервер выполняет SQL-запросы к PostgreSQL и возвращает JSON. Запросы с клиента вынесены в четыре файла `api-*.js`, состояние хранится в контекстах: `AuthContext` — текущий пользователь, `CartContext` — корзина.

## База данных

PostgreSQL. Используется готовая база `phone_shop` (смартфоны и наушники, категории 5 и 6). Используются таблицы:

- `roles` — роли: `1` — `customer` (покупатель), `2` — `admin` (администратор);
- `users` — пользователи (`role_id`, `name`, `email`, `password_hash`, `address`);
- `categories` — категории (`name` — уникальное);
- `services` — товары (`code`, `category_id`, `name`, `description`, `duration`, `price`, `discount_percent`, `image`, `active`);
- `coupons` — персональные купоны (`code` — уникальный, `discount_percent`, `user_id`, `active`); в базе есть уникальные индексы «код уникален» и «одна активная запись на пользователя»;
- `appointments` — заказы (`user_id`, `status`, `total`, `delivery_address`, `created_at`);
- `appointment_services` — позиции заказа (первичный ключ `appointment_id` + `service_id`, поэтому одинаковые товары в заказе объединяются по количеству);
- `payments` — оплата (`appointment_id`, `amount`, `status`, `provider`).

Пароли хранятся в виде `соль:sha256(соль + пароль)`: отпечаток считается функцией `hashPassword`, проверяется функцией `checkPassword` в `backend/server.js`. В открытом виде пароли не сохраняются.

Учётные записи для проверки нужно создать самому — регистрацией на сайте. Чтобы получить администратора, роли `admin` в таблице `roles` должен соответствовать `id = 2`, а созданному пользователю нужно вручную поставить этот `role_id` в таблице `users`.

## Система скидок

- Персональный купон (5%) выдаётся автоматически при регистрации, процент и код купона администратор может изменить в панели.
- Товарная скидка задаётся администратором отдельно от персональной; в чеке и в корзине они показаны разными строками, поэтому суммы сходятся.
- Скидка ограничена 99%, а доля товаров со скидкой не может стать меньше 30% активного каталога: сервер отклонит снятие последней скидки с пояснением в интерфейсе.

## Запуск сервера

```
cd backend
npm install
copy .env.example .env
```

В `.env` указать свои данные подключения к PostgreSQL (в текущей настройке — база `phone_shop`, пользователь `postgres`), затем:

```
npm start
```

Сервер поднимется на `http://localhost:5000`.

## Запуск клиента

Из корня проекта:

```
npm install
npm run dev
```

Клиент откроется на `http://localhost:5173` (если порт занят — Vite выберет следующий) и будет обращаться к API по адресу `http://localhost:5000/api` (адрес задан константой `API_URL` в `src/api.js`).

## Сборка

```
npm run build
```

Собранные файлы появятся в папке `dist` (она создаётся заново при каждой сборке и в репозиторий не попадает). Линтер запускается командой `npm run lint`.

## Проверка работоспособности

Проект проверен сквозными тестами: 60 проверок API (регистрация, вход, профиль, каталог, оформление заказа, история, скидки админа, категории), 43 проверки интерфейса в браузере (каталог, фильтры, поиск, корзина, чек, профиль, админка, разграничение доступа), 51 проверка соответствия требованиям и 14 проверок поведения при недоступном API. Отдельно проверено правило доли скидочных товаров (9 проверок). Сборка `npm run build` и линтер `npm run lint` проходят без ошибок.

Скрипты проверок были временными и удалены — в проекте остался только рабочий код.
